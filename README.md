# relay-node

Публичный установочный пакет узла RTMP/SRT-релея. Узел принимает один поток от
OBS по SRT (рекомендуется) или RTMP и отправляет его на выбранные площадки через
центральную админку.

Поддерживается только **Ubuntu 24.04 LTS amd64** на сервере с публичным IPv4.
В админке IPv4 должен точно совпадать с исходящим IPv4 сервера.

## Установка

Сначала добавьте сервер в админке. Укажите имя, публичный IPv4, максимальное
число моделей и месячную квоту (по умолчанию 32 ТБ). Скопируйте одноразовый код,
но не вставляйте его в командную строку.

На новом сервере выполните:

```bash
git clone https://github.com/Andrey-Panin/relay-node.git
cd relay-node
sudo bash install.sh
```

Установщик сам скроет ввод одноразового кода. Код не попадает в URL, аргументы
процесса, переменные окружения или журнал. Повторный запуск `sudo bash
install.sh` использует уже полученную индивидуальную identity и не требует
нового кода.

## Обновление уже подключённого Relay

Обновляйте только когда в админке у Relay **0 активных трансляций**: команда
перезапускает `relay-agent` и MediaMTX, поэтому текущие эфиры оборвутся.

```bash
cd ~/relay-node
git pull --ff-only
sudo bash install.sh
```

Новый одноразовый код не нужен: установщик использует сохранённую identity.

Сервер появляется в пуле только после локальной проверки и трёх подряд свежих
heartbeat со здоровым MediaMTX и совпадающей ревизией конфигурации. До этого его
статус в админке — `pending/checking`.

## Сеть

- `8890/udp` — SRT-вход из OBS;
- `1935/tcp` — резервный RTMP-вход;
- SSH-порт определяется из `sshd -T` и текущего SSH-сеанса;
- внутренние RTSP, API, метрики и health-check слушают только loopback.

UFW изменяется только после резервной копии. До изменения правил запускается
автоматический откат через 10 минут. Таймер отменяется лишь после подтверждения
админкой, что узел активен в пуле. По возможности откройте второй SSH-сеанс во
время установки.

## Что делает установщик

1. Проверяет ОС, архитектуру, память, диск и allowlist публичного дерева.
2. Создаёт проверяемый backup в `/var/backups/relay-node/`.
3. Ставит MediaMTX v1.20.1 по фиксированной SHA-256. Если GitHub Release CDN
   недоступен, получает свежую подписанную ссылку GitHub и скачивает тот же
   архив напрямую из официального Azure Blob backend; SHA-256 проверяется в
   любом случае до распаковки.
4. Принимает только официальный Noble FFmpeg `7:6.1.1-3ubuntu5` или более новый
   `+esmN` из подписанных Ubuntu-репозиториев и проверяет нужные протоколы.
5. Создаёт неизменяемый versioned release и атомарный `current` symlink.
6. Получает индивидуальные credentials по одноразовому claim и сохраняет их с
   правами root-only.
7. Запускает systemd-сервисы, проверяет listeners/health и ждёт попадания в пул.

Установщик не хранит root-пароль в админке и не предоставляет WEB-серверу SSH.

## Ошибка и повторный запуск

При ошибке установщик восстанавливает конфигурацию и UFW из напечатанного
backup. Версионированные каталоги и `/var/lib/relay-bootstrap` остаются для
безопасного повторного запуска и расследования. Это важно: один и тот же claim
можно повторить после разрыва соединения, не создавая второй relay.

Диагностика:

```bash
sudo systemctl status relay-agent mediamtx
sudo journalctl -u relay-agent -u mediamtx -n 100 --no-pager
sudo /opt/relay-node/current/scripts/verify.sh
```

Не публикуйте вывод, если перед этим не убедились, что в нём нет приватных
адресов или других операционных данных.

## Привязка к менеджеру

Этот репозиторий привязан к `https://89.110.88.252` и содержит только публичный
CA certificate для проверки TLS по IP SAN. Приватного CA key в репозитории нет
и быть не должно. При смене адреса или CA maintainer обязан обновить оба файла
в `bootstrap/`, пересчитать `SHA256SUMS` и дождаться зелёного CI до установки
новых узлов.

Исходный код публично просматривается, но это не open-source лицензия. См.
`LICENSE` и `THIRD_PARTY_NOTICES.md`.
